## 2. The root cause (read this before touching any `<style>` tag)

**React escapes `"` → `&quot;` and `'` → `&#x27;` in the TEXT CHILD of a `<style>` tag. `<style>`
is an HTML raw-text element, so the browser never decodes the entity.** The server DOM contains
`&quot;` while the client render produces a real `"`. They diverge at the first quote → React #425
(text mismatch) → #423 (discards and client-renders the entire root) → #329.

Because `data-theme` is set only by the pre-paint script in `app/layout.tsx:45` and never appears
in the JSX, the rebuilt `<html>` loses it.

This was almost certainly the disease behind the whole theme saga — stripped `data-theme`, the
four-way desync, the dark flash, the `/dashboard` hydration cascade. Confirmed on production
before the fix and 0 on every route after.

Only **four** blocks of ~24 carried quotes: `Header.tsx` HEADER_CSS (every route, the production
culprit), `SiteNav.tsx` (quotes hidden behind `${FR}/${IN}` interpolation), `HeroCompute.tsx`
(a `"₹5,00,000"` CSS comment), `SectionTabs.tsx` (`a[data-active="false"]`). The other ~18 are
quote-free `@keyframes`/`@media` and were correctly left alone.

**Fix is a CSS module or imported `.css` — never `dangerouslySetInnerHTML`,** which bypasses the
escaping rather than removing the tag.

> The comment above `HEADER_CSS` asserted it was *"byte-identical on every server and client
> render… can never produce a hydration mismatch"* — three lines above `[data-theme="dark"]`,
> twice. That comment is why nobody looked there for weeks.

**Two quote-bearing tags still remain:** `app/login/page.tsx:181` (an apostrophe in a comment) and
`app/(shell)/trip-planner/page.tsx:515` (`offset-path: path('…')`). `/login` is on the critical
path into the app.

Note the check `data-theme=&quot;` does **not** detect these — an apostrophe escapes to `&#x27;`,
so `/login` returning 0 does not clear it.

**Retirable once confirmed:** `NavShell.tsx:52` and `Header.tsx:95`, both
`useEffect(() => { reassertTheme() }, [])`. The pre-paint script stays. Not yet removed.

## 3. Tomorrow's focus — signed-in UX/UI

**The merge made this urgent.** A user now moves from a white/cream/teal marketing site, signs in,
and lands on a **dark gold** dashboard. That's the same jolt we spent the week designing out of
the front door, at the single most important transition in the product.

**The direction is already decided (1 Aug): gold is retired, everything goes white/copper.**
This reversed the locked "Amex-Platinum" `[data-ciq]` redesign. CLAUDE.md was partly updated.

**Five surfaces are still on gold:** `dashboard`/WalletView, `feed`, `profile`, `my-cards`, `pro`
— plus onboarding, `Tour.tsx`, the dashboard add-card modal, and Header's mobile menu.

### The thing that will bite
There are **two complete token systems with overlapping semantic names**:

- **System A** — white/copper: `--ink`, `--copper`, `--surface`, `--line`, keyed on
  `creditiq-theme` → `data-theme` on `<html>`
- **System B** — gold: `--ciq-bg`, `--ciq-ink*`, `--ciq-gold*` (globals.css:1454–1486), gated on a
  `data-ciq` **wrapper div** never on `<html>`, keyed on a separate `ciq-theme` localStorage key

They have independent toggles and never sync. `ciq-theme` currently dual-writes as an **interim**.
Picking the wrong system produces no type error and no build failure — `tsc` can never catch
CSS-token drift.

**Known live consequence:** `app/globals.css:231` sets `h1,h2,h3,h4,h5 { color: var(--ink) }`,
pointing every heading at the legacy token instead of `--ciq-ink`. In light mode on `/dashboard`
the greeting, "Your best move", "Your cards" and "Cards to know" render white on white. The fix is
a **contract** — scope the global rule so `[data-ciq]` headings default to `--ciq-ink` — not four
per-element edits.

### Suggested order
1. `/dashboard` — the landing surface after sign-in, and the worst clash
2. `/profile` · `/my-cards` — highest traffic after that
3. `/feed` · `/pro`
4. Then the shared islands: onboarding, Tour, add-card modal, mobile menu

One surface per session, six-docs-first, same as the homepage.

## 6. Standing rules

- **A comment is not a gate. Deletion is.** A comment claiming code is safe is worse than none
- **CSS comments are dangerous here.** Three times in one week: a quoted figure broke hydration; an
  apostrophe is still live on `/login`; a comment describing an anti-pattern triggered a
  false-positive lint finding
- **The code affecting an element is not always named after the element** — `[class*="card"]` could
  not be found by grepping `card-mockup-inner`
- **globals.css is the bug factory**
- **Don't sanction a pattern you want to forbid** — three hand-rolled copies of the theme-write
  logic *was* the bug; a fourth isn't a fix
- **Animation-gated content is a correctness bug, not polish**
- **Read the rendered result, don't reason about it.** Verify against production and check which
  build you're looking at. **A 200 is not proof** — a stray same-named file in the wrong folder
  returned 200 and hid a broken video wire-up for three rounds
- **Don't trust a delegated subagent's catalog** — one hallucinated quotes in
  `@keyframes rotate(360deg)` and missed the real interpolated case in `SiteNav`
- **Nothing invented ships.** Every figure from SEED_CARDS, the engine, or cached fares. If it
  can't be computed, drop the element, not the honesty
- **One number, one meaning.** Two surfaces showing the same thing read from one source
- **The pattern across all of it:** something was true in the source and false at runtime. Tests
  were green the whole time
